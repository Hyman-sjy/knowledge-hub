# 项目计划 — QKH V1.1

## 1. 建设目标
建设质量部门首批可用的统一知识服务，支持文件定位、条款问答、适用性查询、来源引用、反馈审核和候选知识提炼。平台同时建立未来文件生命周期、质量案例、QMS/MES、MCP/插件接入的可扩展基础。

## 2. 已确认事实与约束
- OA：人工下载/导出，无已确认 API。
- 企业微信微盘：尚无 API 应用权限。
- 文件编号和版本规则整体存在，需抽样验证。
- Dify：公司私有部署；当前切片错误率较高，原因待验证。
- 首期：质量部门；入口 Web + 企业微信。
- 资源假设：约 1 名主要 FDE/开发负责人，质量 Owner 每周提供业务核验，IT协助身份、网络和企业微信配置。
- 时间基线：8周目标，2–4周风险缓冲；接口权限和文件治理延误可能延长。

## 3. V1.1 冻结决策
- 三层知识地图：业务对象、需求意图、工具能力。
- 首期完整记录反馈，自动生成候选知识，人工审核/验证/批准后发布。
- 统一 API 和身份权限标准；Web、企业微信首期落地；MCP/插件仅预留契约，按需适配。
- PostgreSQL 为业务主数据；Dify 为编排；Docling/RAGFlow/Dify 做解析基准。
- 首期人工文件接入；不依赖 OA/微盘 API。
- 四类解析策略作为正式规范，按文件类型配置并测试。

## 4. V1.1 第一阶段范围
### P0 必须交付
1. 文件主目录、版本、来源、权威性台账。
2. 四类文件结构化解析：程序/手册、标准/检验规范、Excel表格、通知/会议纪要。
3. 三层知识地图和受控路由。
4. 统一检索 API、Dify External Knowledge 适配。
5. Web 管理/查询端、企业微信员工入口（企业微信身份条件未满足时，Web先上线，企业微信列为受控Gate）。
6. ACL前置过滤、版本过滤、证据定位。
7. 反馈分类、审核、候选知识提炼、候选队列；正式发布必须人工审批。
8. 黄金测试集、解析基准、检索和安全回归。
9. 运营责任、Owner、审计和变更记录。

### P1 首期轻量实现
- 候选知识去重/相似合并建议。
- 知识关系基础关联（文件—条款—产品—检验项目—工艺—部门—案例占位）。
- 知识使用统计与无答案/高频反馈看板。
- 统一 API 的调用方登记和应用身份。

### 不在 V1.1 实现
OA/微盘自动同步、完整文件审批与通知工作流、正式变更影响分析、自动批准/自动发布、QMS/MES实时数据、完整案例库自动推理、GraphRAG/Neo4j、全公司跨部门推广、MCP/插件完整产品化。

## 5. 五期路线
- P0（V1.1）：知识治理、结构化解析、检索、统一 API、反馈候选闭环。
- P1：文件生命周期管理：变更申请、版本差异、关联影响、OA审批、发布通知、阅读确认。
- P2：质量经验知识化：8D/CAPA、异常、客诉、工艺改善案例，验证等级、反例、相似案例。
- P3：智能质量协作：QMS/MES只读数据、SPC、批次追溯、RCA辅助、实验验证。
- P4：企业知识生态：多部门知识域、MCP/插件生态、跨域治理和知识运营。

## 6. 8周计划
| 周 | 任务 | 主要交付 |
|---|---|---|
| 1 | 文件盘点、Docling/Dify/RAGFlow解析PoC、企业微信身份可行性 | G0报告、金标准样本、ADR建议 |
| 2 | 数据模型、三层知识地图、权限、API骨架 | migration、契约、路由配置 |
| 3 | 文件人工接入、解析、结构化元素、切片与索引 | 解析产物、人工复核台账 |
| 4 | 统一检索、版本/ACL过滤、Dify适配 | search/answer-context API |
| 5 | Web管理、查询、反馈、候选知识审核 | 管理端可用 |
| 6 | 企业微信身份、H5入口、应用登记 | 员工端可用或延期Gate |
| 7 | 黄金集、解析/检索/安全回归、试点 | 测试报告、缺陷清单 |
| 8 | 修复、业务验收、运维交接 | V1.1试点交付 |

## 7. Gate
- G0：样本合法可用；来源与Owner清楚；三种解析方案可比较；企业微信身份方案有结论。
- G1：三层知识地图、数据模型、权限模型、API契约通过评审。
- G2：四类解析产物可追溯；表格/条款完整性可测；未确认权威资料不会成为正式答案。
- G3：统一检索、Dify适配、Web及反馈审核可用；候选知识不自动发布。
- G4：黄金集、权限、安全、业务试点通过；知识Owner和运营Owner明确。

## 8. 第二期启动条件
1. 首批正式文件权威性由Owner确认。
2. 版本、来源、条款/页码/工作表定位可追溯。
3. 固定测试集中越权为0、错误版本作为现行要求为0。
4. Recall@5、引用正确率、事实正确率和拒答指标达标。
5. Web及企业微信至少一个员工入口完成真实试点；企业微信未通过身份安全测试不得开放。
6. 反馈可记录、分派、审核、形成候选并人工批准/拒绝。
7. 质量知识Owner、平台运营Owner、文件变更Owner明确。
8. 阻断缺陷清零，业务与IT接受剩余风险。
9. 至少积累真实查询观察数据；样本不足时延长试点，不为凑数造数据。

## 9. 第二期目标
文件变更申请、版本差异、关联文件/业务对象影响分析、OA审批复用、批准后索引更新、企业微信通知与阅读/培训确认。
