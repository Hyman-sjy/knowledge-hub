# 协作与共建规范

## 分工
- 业务 Owner：确认文件权威性、适用范围、答案金标准。
- 文件 Owner：确认版本、生命周期、原始来源。
- 平台 Owner：数据模型、接口、发布和运维。
- IT/安全：身份、网络、权限、密钥、部署。
- 开发贡献者：按任务分支、测试和文档提交。

## Git 流程
- `main` 仅保留可运行、已验证版本。
- 每个任务建立短期分支：`feat/<issue>-...`、`fix/<issue>-...`、`docs/<issue>-...`。
- Pull Request 必须包含目的、改动、测试、风险、截图/日志（脱敏）。
- 数据库迁移、API契约、权限逻辑必须至少一名维护者审查。
- 不直接提交真实质量文件、个人信息、密钥和生产数据到 Git。

## 文档要求
架构/范围变化更新 ADR；行为变化更新 CHANGELOG；测试变化更新 TEST_PLAN；每周更新进度和风险。文档和代码同一 PR 更新。
