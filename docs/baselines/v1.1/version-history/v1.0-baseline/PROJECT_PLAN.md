# 项目计划 — QKH V1.0

## 1. 目标
在质量部门建立可被 Web、企业微信及后续 AI 应用复用的统一质量知识服务。首期重点为受控文件定位、条款问答、适用性查询、来源引用和反馈闭环。

## 2. 已确认事实
- OA 文件当前需要人工下载/导出，无已确认 API。
- 企业微信微盘尚无 API 应用或授权。
- 文件编号和版本规则整体存在，仍需抽样核验字段完整性。
- Dify 为公司内置私有部署。
- 当前 Dify 切片/返回信息存在较大错误率，原因尚未通过基准测试定位。
- 第一批范围为质量部门；入口为 Web + 企业微信。
- 首期建议样本 20–50 份代表性文件。

## 3. 范围内
- 文件主目录和多来源登记。
- 权威性/生命周期/索引状态分离管理。
- 版本、来源、适用范围、责任人、密级元数据。
- 人工批量导入和文件指纹去重。
- Docling 解析 PoC、自定义结构切片。
- Dify 与 RAGFlow 对照基准。
- 统一检索 API、Dify External Knowledge API 适配。
- Web 管理及查询界面、企业微信 H5 入口（企业微信集成按权限可用性设 Gate）。
- 用户身份映射、服务端 ACL、查询日志、反馈审核。
- 黄金测试集、解析测试集、回归测试。

## 4. 范围外
OA/微盘自动同步、文件审批/发布/自动通知、QMS/MES 实时查询、案例库深度推理、完整知识图谱、视觉识别、自动训练/微调、自动把反馈写入正式知识。

## 5. 8 周计划（目标，不是承诺）
| 周 | 工作 | 交付 |
|---|---|---|
| 1 | 数据盘点、权限访谈、解析与检索 PoC | 样本清单、来源台账、PoC 报告 |
| 2 | 项目骨架、数据库、身份/权限模型 | 可运行骨架、迁移、接口契约 |
| 3 | 文件接入、解析、结构化切片、版本登记 | 首批文档入库、解析审阅界面/报告 |
| 4 | 检索服务、路由、Dify 适配 | search API、外部知识 API |
| 5 | Web 管理/查询端 | 文件目录、详情、测试、反馈 |
| 6 | 企业微信入口与身份映射 | H5 查询及反馈 |
| 7 | 回归、安全、用户试点 | 测试报告、缺陷清单 |
| 8 | 修复、验收、运行交接 | V1.0 试点版本、运维手册 |

若企业微信权限或员工身份映射未能及时获得，Web端可先验收；企业微信 Gate 单独延期，不得用共享账号绕过身份控制。预计缓冲 2–4 周。

## 6. Gate
- G0（第1周）：来源盘点完成；20–50份样本可合法用于测试；企业微信 API 可行性已确认或形成降级方案；完成解析对比计划。
- G1（第2周）：数据模型、权限模型、API 契约及 ADR 评审通过。
- G2（第4周）：解析产物可追溯；检索结果能返回版本/条款/来源；权限前置过滤通过。
- G3（第6周）：Web 查询、文件查看、反馈闭环可用；企业微信集成通过身份测试或明确延期。
- G4（第8周）：黄金集、异常测试、安全测试、业务试点和运营责任通过。

## 7. 第二期启动条件
必须满足：
1. 首批正式知识文件权威性已由文件 Owner 确认。
2. 文件版本、来源和条款定位可追溯。
3. 固定测试集无错误版本被作为现行要求返回；权限测试无越权。
4. Recall@5、证据引用、拒答指标达到 `TEST_PLAN.md` 门槛。
5. Web 和至少一个员工入口已在质量部门试点。
6. 反馈可记录、分派、审核、关闭。
7. 知识 Owner、平台运营 Owner、OA 文件变更 Owner 明确。
8. 重大缺陷清零，剩余风险经业务与 IT 接受。

建议观察样本：不少于 100 次真实查询；反馈不足时不得为了凑数造数据，可用人工构造用例补充功能测试，但不能替代真实采用验证。

## 8. 第二期方向
文件变更差异、关联文件影响分析、OA审批衔接、批准后索引更新、企业微信通知与知悉确认。优先复用 OA 审批，不重复造审批系统。
