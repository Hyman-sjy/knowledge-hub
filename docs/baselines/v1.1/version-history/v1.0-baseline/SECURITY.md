# 安全、权限与数据治理

## 1. 安全原则
- 默认拒绝（fail closed）。
- 最小权限；按用户、角色、部门、文件密级授权。
- 权限检查在检索前执行，不能依赖 Prompt。
- 模型不拥有审批、授权、文件状态修改权限。
- 原文件下载必须重新做服务端授权，不暴露永久公开 URL。
- 不将受限文件内容写入普通应用日志或第三方服务。

## 2. 身份
企业微信身份需通过可信 OAuth/企业内部身份流程验证并映射到内部 users。Web管理端使用公司认可的 SSO/身份方案。不得共享管理员账号，不接受客户端自报 user_id。

## 3. 文档安全
每份文档具备 classification、ACL、Owner、source system。导入前确认用途和授权范围。对外部/用户上传内容进行提示注入防护：文档内容一律视为数据，不视为系统指令。

## 4. 权限失效策略
身份服务、ACL服务、来源授权状态不可用时拒绝访问。Dify 外部知识适配器必须传递可信身份上下文；若当前 Dify 调用方式无法安全传递终端用户身份，不得开放用户级受限文档，只能使用明确批准的公共/部门共享知识域。

## 5. 审计
记录查询人、时间、请求ID、意图、命中文档ID/版本ID、权限决策、反馈和管理变更。避免记录完整敏感正文。日志保留期限由公司制度和 IT 确认。

## 6. 上线前检查
密钥管理、HTTPS、CORS、CSRF、速率限制、上传文件类型/大小校验、恶意文件扫描、SQL注入、越权测试、提示注入测试、日志脱敏、备份恢复、依赖漏洞扫描。
